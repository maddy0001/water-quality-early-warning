💡 PREPROCESSING DESIGN DECISIONS:
================================================================================

1. Why KNN Imputation?
   ✓ Better than mean/median for correlated features
   ✓ Preserves relationships between features
   ✓ Research-backed for water quality data

2. Why SMOTE?
   ✓ Better than random oversampling
   ✓ Creates synthetic samples in feature space
   ✓ Reduces overfitting on minority class

3. Why 30-day Lookback?
   ✓ Captures monthly patterns
   ✓ Sufficient for temporal dependencies
   ✓ Not too long (memory efficient)

4. Why Train-Val-Test Split?
   ✓ Validation for hyperparameter tuning
   ✓ Test for final evaluation
   ✓ Prevents overfitting

5. Why MinMax for Forecasting?
   ✓ LSTM works better with bounded inputs
   ✓ [0, 1] range matches activation functions
   ✓ Faster convergence

Methodology Section Content:

3.2 Data Preprocessing

3.2.1 Classification Pipeline
"Missing values in the potability dataset (pH: 15%, Sulfate: 23.8%, 
Trihalomethanes: 4.9%) were imputed using K-Nearest Neighbors (k=5) 
to preserve inter-feature relationships. Outliers were detected using 
the IQR method (threshold=1.5) and removed to improve model robustness. 
Features were standardized using StandardScaler. Class imbalance 
(61% non-potable, 39% potable) was addressed using SMOTE oversampling, 
resulting in a balanced dataset of approximately 4,000 samples."

3.2.2 Forecasting Pipeline
"Temporal sequences were generated using a sliding window approach 
(lookback=30 days, horizon=1 day, stride=1). This produced 14,541 
training sequences from 423 days across 37 spatial locations. Features 
were normalized to [0,1] range using MinMaxScaler. Data was split into 
60% training, 20% validation, and 20% testing sets, maintaining temporal 
order to prevent data leakage."
